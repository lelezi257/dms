01 · 先固定抽象语义，再命名代码

设计选定 本章是术语权威。它定义业务边界，不预先固定 Rust 字段布局或 proto 字节格式。“根目录”指一个受管理的 workspace 根，并非每次 mkdir 都产生新根。

抽象 / 建议类型名准确含义与权威边界
命名空间 NamespaceIdWorkspace 与 Image 是隔离的业务命名空间；同一 FUSE 接入层按挂载视图、身份和后端类型分派。独立授权、inode 身份域和缓存键；彼此不能查到对方文件。管理视图可列两个入口，沙箱视图只暴露获授权部分。
工作区根 WorkspaceRoot / RootId例如 /workspaces/job-42。Master 管理稳定 ID、名字、存储节点和生命周期。src、logs 等子目录继承此根。RootId 不依赖可变路径名。跨根 rename/link 首版返回 EXDEV；不把每个子目录注册到 Master。
存储位置 DataHome这个根唯一一份可写文件树所在的 Worker 节点。管理面提供位置查询给调度器。是位置属性，不是进程或模块名。Agent 换计算节点不自动迁移数据。
根访问授权 RootGrantMaster 决定哪个 Worker 会话可访问该根、当前是本地独享还是远端参与。Worker 持有并在内存校验授权。目录归属、节点注册、发现 IP 均不等于读写授权。读者也会触发首次跨节点协调。
根世代 / 授权代 / 会话RootEpoch 防删除重建/迁移后的旧请求；AccessGeneration 防旧模式继续用；WorkerSession 区分进程重启。切换共享不改变文件身份；三种世代不混成一个随意递增的文件版本。旧挂载 FD 不透明续接。
文件身份 FileIdentity / 句柄 FileHandle本机文件系统保存文件真相；Worker 为已打开文件持有真实 FD，远端持有不透明句柄。FUSE inode 只是本次挂载映射。路径、inode 数值都不能单独防同名重建/编号复用。旧 FD 不能误操作同名新文件。
私有写层 ImageDraft绑定单个沙箱/写者及 Worker 的可修改文件树或磁盘文件；可持续写入，只有获授权的写者可见。普通文件表示；不逐文件 seal，不逐写生成 Blob。不同沙箱有各自 draft。
稳定切点 SnapshotCut运行时协调停写、排空 I/O 后取得的不可再被后续写入修改的视图。文件系统一致的内容快照不自动等于应用事务一致，也不包含 VM 内存/设备状态。
快照版本 SnapshotVersion已原子发布的固定 ID；绑定 manifest 摘要、版本依赖和持久副本策略。旧版本永远不改。Alias 只是可条件更新的版本指针；读者解析后固定 VersionId。
索引 ImageManifest文件树属性、目录项、链接、内容范围、必要 xattr；或磁盘文件的逻辑长度/范围。记录父版本与删除语义，或完整物化视图。仅打包 upper 而丢弃 parent、whiteout/opaque 信息不能重建 rootfs。索引作为不可变对象保存，不把每个文件条目塞入 Master。
不可变对象 Blob / 范围 BlobRangeBlob 为封存并校验的物理对象；BlobRange 把逻辑文件偏移映射到对象区间，小文件可共用 pack。只属于镜像后端。封存一个 Blob 是打包动作，不等于一个沙箱版本发布。
传输片 TransferChunk传输/分段校验/续传的单位，可多片共用一次流式 RPC。不是 Workspace 文件分片，也不是每片必需一次网络往返。
持久副本 / 缓存 / 读引用Replica 参与耐久承诺；CacheEntry 可驱逐；VersionPin 在读取时防回收。副本位置、缓存位置、访问授权分开；读者不能靠无限旧缓存绕过删除/权限检查。
两条独立生命周期： WorkspaceRoot → 本地独享 → 远端参与 → 撤销远端后恢复独享；ImageDraft → SnapshotCut → 后台构建 → SnapshotVersion。两者没有隐式互转，显式导出才跨边界。共享 workspace 仍然读写普通文件。

02 · 进程、模块与部署关系

每节点一个 afs-worker 进程。 FUSE 前端、workspace 本地执行器、P2P 服务和镜像模块均在进程内调用；不用 Home 命名进程。另有 afs-master 控制进程，部署可与 Worker 同机，但角色和故障边界分开。运行时适配器由沙箱侧集成，不属于另一个文件系统客户端。

框内是模块，不是多个进程；Worker 内部没有 FUSE→本地服务的网络 RPC。读者与副本角色可在任一 Worker。Master 1/3 节点与 Worker 2–4 节点是不同维度。

归属 / 建议模块名职责与核心动作明确边界
Worker / FuseFrontendPOSIX/FUSE 适配、挂载 inode/handle 生命周期；调用 NamespaceRouter。不拥有持久目录树；不能独立签发根授权。
Worker / NamespaceRouter + RootAccess从父 inode 的后端身份找根，首次 resolve/acquire，缓存合法 RootGrant；协调模式切换与缓存屏障。已授权热路径不逐操作查中心；两个 namespace 的权限与缓存分域。
Worker / WorkspaceService同一个本地执行器处理 FUSE 本地调用与已授权 P2P 调用，直接操作 native 文件。无逐写不可变对象，无本地第二套文件内容事实源。
Worker / PeerClient、PeerService节点直连、会话/文件身份、批量和流、错误映射；两后端复用连接工具。WorkspaceOp 与 BlobTransfer 业务协议分开；连接认证不是文件授权。
Worker / ImageService内部 DraftManager、SnapshotBuilder、ImageReader；接收 snapshot 请求、稳定视图、打包复制、范围读。不能根据 close 猜发布；不能把活跃 workspace 自动转 Blob。
Worker / BlobStore不可变对象本地落盘、分段校验、暂存、副本保留与缓存驱逐。不是新增通用 S3/多写对象产品。
Master / RootCatalog + AccessCoordinator根名字/位置/生命周期、访问授权、撤销确认、管理查询。不逐文件建索引；不代理内容。
Master / ImageCatalog + Placementdraft 写者、发布计划、版本/别名/引用、副本放置及保留记录。大 manifest 和内容留 Worker；节点健康不冒充可读授权。
Master / MetaStore条件事务、权威读取、有序修订、恢复和选主围栏；先 etcd adapter，后嵌入 Raft。只抽象真正要替换的控制存储，不预造通用业务引擎。
沙箱侧 / RuntimeAdapter识别 snapshot 时机，协调 pause/flush/capture/resume 与 rootfs 装配。它是显式生命周期集成，不靠 FUSE 猜沙箱是否写完。

命名依据：3FS 把 client/meta/storage 职责分开，Nydus 区分 daemon 与镜像构建工具，AgentENV 有显式快照管理；AFS 借其职责边界，合并适合近计算节点的执行模块。旧预览代码 main.rs 已在同一进程启动 FUSE session 和 P2P server，上一版时序把 Home 画成独立进程不准确。

03 · Workspace：先根授权，再本地操作

A. mkdir 到本地热路径：哪些需要中心，哪些不需要

  1. 先解析根。 FUSE 的 mkdir 通常给父 inode 与名字，而非完整绝对路径。NamespaceRouter 从父 inode 的 NamespaceId/RootId 识别所属根；仅在 workspace 容器下新建一级目录时才创建新 WorkspaceRoot。root 内的 mkdir 继承父根。不能靠拼接路径字符串猜归属。
  2. 首次建立授权。 新根按图走 reserve/本地准备/activate 两次 Worker→Master 请求；两个节点同时建同名根由条件事务只准一个生效。已有根首次访问可把 resolve 与 acquire 合成一次请求。Master 可选择远端放置，默认先用本机；远端准备会额外增加一次节点请求，不能算成本地路径。
  3. 随后全本地。 有效的 LOCAL_EXCLUSIVE(A) 授权表明仅 A 的当前 Worker 会话获准访问；A 的同机多个进程可使用本机文件系统的一致性。内层 mkdir、open、write、rename 不再逐次查中心；实际内容保持普通文件。下层数据目录仅供 Worker 使用，绕过 AFS 的直接外部改写不在合同内。
  4. 归属与授权不同。 查询接口可让调度器提前得知 DataHome=A，但调度器查询不授权任何读写。缓存的根位置不能让 B 未经协调就访问 A 的文件。

B. B 首次来访问：A 的 ACK 是放行前提

② 是 Master→A 一次带 ACK 的回调，包含于①的等待时间。A 在回 ACK 前只准备好接受 已提交的新授权，不会放行裸请求；B 的新授权返回后才能执行③。A 的本地接入在屏障完成后可按原有效身份恢复保守模式；它不恢复独享缓存权，只有读取到已提交的独享状态才可再次升级。A 把访问代的保守下界记入根控制标记，重启仍须与 Master 对账，不能从旧磁盘状态自行恢复独享。Master 重启按 transition ID 和条件事务继续，重复通知/ACK 幂等；过期会话的 ACK 无效。

三个阶段只有一份可写数据： LOCAL_EXCLUSIVE：只 A 获授权；REMOTE_ACTIVE：B 获授权、数据仍在 A；A 与 B 都有访问者时也是 REMOTE_ACTIVE。这里不叫“多个 owner”，因为文件权威始终只有 A。B 独用与 A/B 共享可按访问者集合区分，不另造文件存储模式。

C. 缓存与 close-to-open：不是两个 workload 互相失效

Workspace 与 Image 文件互不可见、缓存键不重叠。此处协调的是A、B 访问同一个 WorkspaceRoot。镜像的已发布 VersionId 不变，内容缓存无需跟 workspace 写入一起失效。名称别名、权限与版本生命周期仍需重验证。

首版保守基线 Workspace 数据句柄先用 FUSE direct-io，保持底层普通文件的 Linux page cache；不启用 FUSE writeback-cache。独享时可缓存属性/目录项，共享时 TTL=0，并在切换屏障中失效已有 inode 属性与正负目录项、阻止旧回调重新安装缓存。FUSE direct-io 不等于底层文件 O_DIRECT，也不等于每次写都 fsync。 额外开启独享 FUSE 内容缓存是后续受门禁的优化；未证明旧 FD、脏页和并发失效前不纳入性能通过数据。（Linux FUSE I/O 模式）

A/B 的写先在 A 的同一份底层文件完成，成功关闭前排空该打开实例的写请求；FUSE flush 路径需传播错误，不能只依赖异步 release。后续 open 重新在 A 核验身份、长度与属性，再读 A 的内容。无未协调的 B 数据缓存时，这给出 close-to-open；旧打开句柄上的并发读不是稳定快照。共享可写 mmap、分布式锁等只有单独证明才支持，不能把 TTL=0 当作万能修复。

D. 撤销、重启与无法取得 ACK

情形必须发生的动作结果
A 不回复 / 屏障失败Master 保持转换未完成，不给 B 新授权。A 若已降级，保持保守模式直至对账。宁可该根暂不可跨节点访问，不根据超时假设缓存已经撤销。
B 离开，要恢复 A 独享Master 提交撤销中间态；B 排空并确认不再使用旧授权，A 阻止新远端请求并排空在途操作；确认后提交更高代独享。重获独享是低频操作；首版可保持共享模式，不自动按空闲时间升级。
B 已断联，不能 ACK本版不因租约/心跳超时自动恢复独享；等 B 会话可确认终止并完成围栏，或继续保守共享。避免 B 内核仍用缓存/挂起请求，而 A 自以为独享。
A Worker 重启新会话先读根事实、对账 Master、恢复保守访问代，再提供新 mount/open；旧授权和远端句柄失效。本地 FUSE 与本地服务同进程死亡，是一次 Worker 故障；旧 FD 不续接。
Master 无多数派或断联既有有效根会话可继续既有模式；任何新的授权/模式改变/创建删除暂停。Master 恢复仍须遵守原授权记录，不能拿 leader 变化代替 Worker 撤销。
Agent A→B→A 调度变动的是计算位置与访问者集合，DataHome 不变。无需迁移文件；回 A 后可先按保守本地路径工作，再低频收回独享缓存权。

E. 根删除、同名重建与创建中断

  1. 根内普通 rmdir 直接由文件执行器处理；删除 WorkspaceRoot 则由 Master 条件提交 DELETING，保留名字并停止发新授权。DataHome 安装新的路径操作屏障，撤销并排空旧授权下的路径修改，确认后以 native rmdir 原子判空删除；不是递归删除全部内容。远端不能仅凭缓存的旧 RootGrant 绕过屏障。
  2. 目录非空时返回 ENOTEMPTY，按新访问代恢复可用状态；中途故障保持删除中间态，不立即放开名字。成功删除后保存本机结果并同步必要父目录，Master 据此提交 tombstone 才释放名字。新建同名根获得新 RootId/RootEpoch。若删除结果不确定，先对账本机事实与操作 ID，不能把超时当作失败后另建。
  3. 已打开且先前已 unlink 的旧文件，仍按原 FD 语义持有到关闭；保留句柄只允许访问原对象，不拥有旧根的新路径权限，也不会重绑定新根。Worker 崩溃后仍按旧 FD/远端句柄不可透明续接的合同处理。
  4. 创建卡在 PREPARING 时同理保留名字：核对根标记和物理目录，按操作 ID 完成 activate 或撤销；ACTIVE 根若磁盘目录丢失则报故障，不偷偷创建空目录冒充恢复。创建、删除的响应丢失均通过原请求号查询结果。

正常控制面故障转移不重新分配 DataHome。若今后真的迁移数据，必须另走停止旧写者、持久复制、验证、切换归属与 RootEpoch 的协议；Master 的 Raft 不能凭空复制 workspace 文件。

04 · 镜像：持续写 upper，运行时显式请求快照

A. 文件系统需要知道“要快照”，但不能自己猜“写完”

新增的是生命周期接口，不是要求应用改 POSIX 写法。 Agent 继续普通 open/write/close；沙箱管理器在执行 snapshot 时调用 Worker 的 RequestSnapshot(draft, operation_id)。返回“已受理 / 已取得切点”与“已发布”是不同状态。单个文件 close、fsync、暂时没有写入，都不触发 seal/publish。把这些事件当作完成信号会封住后续合法写入。

目录层面的 Draft 单写者表示一个沙箱的授权域，该沙箱内部可以有多个进程/FD。RuntimeAdapter 必须暂停所有会修改它的执行者、处理尚未完成的写入，再建立稳定视图。gVisor 文件树保存 base/upper 合成关系；Firecracker 需要协调 guest/VMM 写入与磁盘同步。只有停 VCPU 而不处理在途 I/O，不足以证明切点稳定。无法取得应用级 flush 时应标为 crash-consistent，不能声称应用事务快照。

  1. 初始化与持续写。 CreateDraft 一次控制请求确定写者、节点、base 版本与 pin。其后对已在 upper 的文件或新建文件，写入用本地普通文件，无 Master/复制 RPC；若首次修改一个仍在远端 base 的文件需要 copy-up，先拉取所需旧内容，这笔 P2P 读取另计，不能藏进“本地写”。一个 shared FUSE daemon 可同时服务两后端，但 draft 只有所属写者身份能访问。
  2. 固定切点。 BeginSnapshot 为操作去重、固定 draft generation、保护父版本及暂存副本。暂停写者后，用受支持的文件系统快照，或停写期间完成 reflink/复制并保存目录/文件属性。逐文件 reflink 本身不是目录原子快照，必须覆盖全部文件的稳定期间；若不支持快照/COW，整个复制期必须停写。只有稳定视图与恢复记录已保存，才报告 cut-ready 并恢复写者。
  3. 继续写不会修改旧切点。 能隔离 COW 视图时活动 draft 可继续在原路径写；否则准备独立活动副本并由运行时接回。不是强制每次替换应用路径/FD。切点之后的字节归下一快照；失效/重启后的不完整切点不复用同一个已承诺版本。
  4. 正确表示 upper。 首版优先导出完整逻辑 rootfs 视图，可复用已发布 base 的不可变范围；使用分层索引时必须保留 parent、whiteout/opaque、链接、权限与必要 xattr，并限制依赖链。裸 upper 压成包不能直接等同完整镜像。
  5. 后台准备与发布。 A 打包/计算摘要，向不同物理节点复制 Blob 与 manifest。复用已发布 base 范围可只保留引用；选择完整物化而本地缺失 base 内容时，额外读取这些范围。持久收据覆盖完整对象与恢复所需的本地索引；提交前保护暂存对象，不能被 GC 当孤儿删掉。副本收据绑定发布操作和内容摘要；保持保留责任直到 Master 明确提交转为版本引用或确认中止。不能只因本地超时就删除已出收据对象，再让旧收据参与提交。CommitVersion 只写有界版本指针/摘要/依赖/副本证明，不逐文件向中心发布；版本与别名条件更新在一个事务中完成。后台复制可以异步于 Agent，但不能异步于“已发布”成功。

B. 新沙箱在 B 启动

读者 pin 按版本/会话管理，不按每个文件建立中心引用。Pin 续租/释放属于单独计数的控制流；读者不能无限期脱离保留协议仍要求 GC 保证。别名更新后，已打开版本仍固定旧 ID，不混读新旧内容。未来磁盘范围懒加载需要额外块层适配，当前不把这部分收益计入首版。

C. 3FS 的机制能直接解决这个问题吗？

不能直接套用。 本次白盒审查 3FS 22fca045 的 Meta API、FUSE 和存储路径，没有发现“私有 upper → 沙箱稳定切点 → 不可变工件发布”的完整业务机制。close 主要收敛文件长度/时间/写会话，不禁止以后修改；FS_IMMUTABLE_FL 可拒绝新写打开，但不等于冻结现有 FD 或整个目录树。其 snapshotLoad 是 FDB 的事务读选项，不是文件数据快照。

3FS 文档描述应用写临时目录后 rename，或在新增独立文件的数据集中用链接组织轻量快照。硬链接不能隔离原文件后续覆盖写。 可借鉴显式完成边界与批量 I/O，不能据此省掉 AFS 的 RuntimeAdapter。Nydus 的构建产物与运行读取分开；AgentENV 的工件导入后再提交目录，也支持“先完整准备、再显式可见”的分层思路。

（3FS：公开 Meta API、close、immutable 检查、应用发布习惯；Nydus；AgentENV）

竞品：比较真实路径，不编造统一的 RPC 常数

系统 / 对齐前提从代码看见的交互AFS 的收益依据与不能偷换的条件
AFS 本地 workspace / 私有 draft有效根/写者授权后，对本地已有文件或新文件的操作 0 远端 RPC；镜像首次 copy-up 所需 base 读取另计，快照时集中支付复制/发布。减少近计算 workload 的逐文件网络工作。私有数据单副本；不能冒充与逐写多副本等耐故障。
3FS：父目录已解析，无重试create+open：1 次 Meta create；已有文件写 open：1 次 Meta open；缓存 inode 的只读 open 可 0。普通 write 通常 0 Meta，数据去复制链；dynamic stripe 扩展额外查 Meta。flush 可 sync，写 release 再 close。减少的是文件级元数据/会话及远端数据路径，不是声称 3FS 每次 write 都找中心。副本数、FDB 内部网络、RDMA 和 batch 另计。
MooseFS：已建连接，未重试客户端文件创建/打开与 Master 协调；写后台有 writechunk 获取布局/许可、直连 chunkserver 的数据会话与 writeend。缓存、合并、分块会改变实际次数。不能把每次 POSIX write 算成一次 writechunk。对照必须说明复制策略、fsync 与缓存；本地小文件可免文件级中心交互，远端共享不预设领先。
Nydus：已生成不可变工件索引/内容分离，按需取内容并缓存；生成、上传、registry 发布由完整工具链决定，不是统一一条 RPC。借鉴 bootstrap、pack、校验、预取；AFS 的 runtime snapshot 与副本提交是额外责任。发布整体 RPC 不拿 reader 单次读数字代替。
AgentENV：快照仓库路径导入快照工件后提交目录；P2P 广告与具体后端/工件数相关。借鉴显式快照 API 与提交边界。未 trace 完整部署前不声称其发布固定需要多少 RPC，也不声称 AFS 已更快。

白盒证据：（3FS）写 open、create、flush/release、扩展 stripe、批量数据 I/O；（MooseFS）FUSE 回调、写缓冲/写会话。3FS 本次固定本地审计版本；MooseFS 链接是核对时上游 master，正式测量必须记录测量提交与配置。

实现门禁： 每个代表 case 从 POSIX 请求关联到 FUSE、授权、Peer、native I/O、MetaStore 提交，记录调用数、消息数、bytes、排队、同步和 p50/p95/p99。主场景若出现逐写中心调用、逐小文件镜像提交、同机内部 RPC，先审查设计偏离，再做微优化。竞品精确次数需固定版本/缓存/复制配置后 trace；本节是设计预算和静态路径证据，不是假装已经实测。

06 · Master：先 etcd，后可嵌入 Rust Raft

可以内嵌，但“有 Raft 库”不等于“已有完整可靠元数据服务”。 OpenRaft 与 raft-rs 都可作为 Rust 共识基础。AFS 仍要实现持久日志、业务状态机、快照恢复、网络传输、成员管理和故障验证。首版采用 etcd 权威后端；后续内嵌优先评估 OpenRaft，不在本轮增加依赖或承诺版本。

RustFS 的 Raft 说法本轮未证实。 官方架构说明其为 MinIO 风格去中心化对象存储。本次核对 upstream edcc81a8 完整 tree、Cargo.toml、Cargo.lock、ARCHITECTURE.md，没有发现 raft/openraft 路径或依赖证据；不能把“RustFS 已经这么做”作为 AFS 依据，也不据此断言所有历史/分支都没有。（RustFS 架构；核对依赖）

首版

AFS Master 业务命令 → MetaStore → etcd。选主资格、根状态、epoch、命令去重和提交结果受同一事务权威约束。不能只在 etcd 拿锁，却往另一个无围栏本地库任意写。

后续内嵌

相同业务命令 → MetaStore → OpenRaft + 持久存储。Master 的 1/3 实例自己形成共识组，去掉外部 etcd 运维依赖；业务语义可保持，迁移与故障验证仍需单独完成。

后端必须等价的合同

能力业务为什么需要
线性一致权威读 + 原子条件事务检查根 revision/epoch/state 再更新；版本与别名条件提交；旧主的权威写资格检查也在事务条件内。
持久提交 + 请求去重ACK 前达到当前模式的持久条件；操作 ID 与控制结果同事务写入，超时查询不产生双重控制结果。
顺序 revision + 恢复watch 可从 revision 续接，压缩后重取权威快照；恢复正在撤销的根、正在发布的操作。
Leader/Worker 会话围栏不让旧 Master 签发新授权，不让旧 Worker 会话重用新授权。业务提交须带正确权限代与状态条件。
可替换且可迁移业务不依赖 etcd key 编码；后续迁移暂停权威修改、导出一致快照、延续 epoch/命令结果，切换后故障复验。不是更换一个 KV 驱动就完事。

部署模式必须明示： 单节点控制存储只能承诺该盘持久，不容忍该节点/磁盘永久丢失；三节点共识组按多数派 2 提交，可容忍 1 节点故障。首版 etcd 按 1/3 成员配置，Master 服务副本数另行配置；后续内嵌时与 1/3 Master 成员对应。三成员须处于独立故障域；只有两台物理机器时，不能把同机的两个实例声称为三物理故障域。

镜像 Blob 与 manifest 仍要求至少两个物理节点持久副本；版本可见性的控制提交遵循所选 MetaStore 模式。使用单节点控制面时，即使内容有两份，也不能宣称整个版本目录能抗中心永久丢盘。上一版“单主 + 手写双份同步控制日志”方案撤下，避免同时维护自制镜像日志和共识后端两套机制。

三个不能等同： watch 已发送 ≠ A 已完成撤销；中心 lease 到期 ≠ A 已停掉本地写；Raft 元数据高可用 ≠ Workspace 数据已有副本。B 获新权仍须等待 §03 的 A ACK。无法证明旧写者已停止时保持不可用，不靠共识选举推测数据面安全。

etcd 的权威事务和 watch 有不同保证；watch 可延迟，不能用它替代撤销屏障。普通 Redis/Sentinel 不列为等价权威后端，Redis 官方明确 WAIT 不能使其成为强一致存储，故障切换仍可能丢失已确认写。（etcd 保证；Redis WAIT）

内嵌库参考：OpenRaft 接入责任、权威读取协议、raft-rs 模块边界。Rust 库选择实施时固定已验证版本。元数据共识只进入根授权与版本发布等慢路径，不增加已授权本地每次 write 的 RPC。

07 · 可靠性：每个 ACK 到底承诺了什么

成功边界承诺不承诺
Workspace write本机文件或远端 A 执行器实际接收的字节数；短写准确返回。每次 write 都抗 VM/磁盘断电；未完成写可留下部分修改。
Workspace close / reopen先完成本次打开的写请求，再重新在同一存储权威上打开与读取；共享路径无未协调的数据缓存。旧 FD 上并发读是稳定快照；release 无条件等同成功 close。
Workspace fsync/fdatasyncA 底层文件系统完成对应同步；创建文件的目录耐久另按目录 fsync 合同。另一节点已有 workspace 副本。
Root 撤销 ACKA 已排空相关旧路径、完成缓存屏障并安装新授权代的保守状态。仅表示通知送达；无法执行屏障也可以先授权 B。
Snapshot cut-ready稳定视图和可恢复操作记录已固定，后续写不会改变它。版本可被外部读者看到，或数据已跨节点备份。
Snapshot published数据与 manifest 满足版本副本策略，MetaStore 已原子提交完整版本/依赖。单 Master 模式也能承受 Master 永久丢盘。数据副本与控制面容错分别声明。
故障切点恢复或可用性结果拒绝错误推断
Worker/FUSE 同一进程死亡普通文件仍在；新 Worker 新会话对账后重挂载、新 lookup/open 重建映射；旧远端句柄 ESTALE。不能只凭旧 grant 本地文件自动恢复授权；旧挂载 FD 不透明移交。
撤销 ACK 之前 / 之后 Master 故障持久 TRANSITION 可恢复；重复请求按 transition ID 处理，未提交新 grant 不可被 B 使用。watch 缺消息、通知丢失或超时都不能当 ACK。
Workspace 所在节点离线/永久丢盘仅该根不可用；等原节点恢复，永久盘损首版不保证数据恢复。选举 Master 不等于安全迁移 DataHome。
共享非幂等修改执行后断回复按操作 ID 查询可知结果；无法证明结果时返回不确定错误，由应用检查状态后决定。请求 ID 本身不能给 append/rename/O_TRUNC 带来 exactly-once；不盲重放。
快照暂停 / capture 中崩溃Incomplete cut 不发布；运行时根据阶段决定恢复/重试，原有已发布版本不受影响。不能扫描还在变化的目录充当同一个稳定切点。
已复制但未提交 / Commit 回复丢失持久暂存 pin 保护对象；按 OperationId 查询发布结果；条件重试不生成两份冲突版本。超时不等于未提交；不能立即清理可能已发布对象。
一个镜像副本坏/离线校验失败换可信来源，告警并修复持久副本；足额新副本前不宣称新发布达标。缓存数量不能满足持久副本数；副本节点永久故障不能返回未经校验内容。
删除版本与活动读者并发先停止新 pin；活跃 pin/父版本引用保护可达 Blob，释放后按保留策略回收。删除别名不等于可以删除所有被引用内容。
Namespace 交叉访问全链路键包含 NamespaceId，权限校验在 Worker 服务端再次执行；跨后端 rename/link 拒绝。统一 FUSE 根不授予读取另一个 workload 文件的能力。

首版不变量：一个根只有一个可写数据位置；无撤销屏障不授予冲突访问；一个版本永远指向同一完整内容；活动读引用不被 GC 删除。更高可用、完整 POSIX、共享 mmap 和透明非幂等恢复要分别增加机制与证据，不隐含在“用了 FUSE/P2P/Raft”里。

08 · 先保证正确，再兑现各自的性能

近计算与 P2P 是架构定位：计算与存储 worker 共置，workspace 优先把 Agent 调度到 Home；镜像优先利用运行节点的持久副本或已校验缓存，缺失时从其它 worker 直接获取。Master 负责位置与权威，不代理数据流。P2P 描述数据面直连，并不取消 Master 控制面，也不意味着数据永久固定在最初写者。位置查询同时服务调度与数据源选择。

验收除延迟外还要量化本地操作/字节占比、每任务跨节点字节、镜像各读源流量、启动时回源放大及 Master 数据转发字节（应为零）。本地性与 P2P 减少绕行是机制依据；收益大小按工作负载实测。

路径基础开销下界 / 优化方向需要白盒观察什么
本地 Workspace W1Native FS 是机制参考上界，薄 FUSE 是该入口的成本参考；复用根目录/数据根 FD，减少重复路径解析、回调拷贝与无谓属性请求。FUSE lookup/open/read/write、下层文件 I/O、权限、缓存命中、CPU 与 syscall 分布；同场与默认 MooseFS 比较。
远端 P2P W2/W3批量/合并可合并的请求、连接复用、读打开元信息与小内容同返、按请求范围传输；共享缓存失效成本必须计入。一次应用操作产生的 RPC 数、RTT、排队、A 端文件 I/O 与 B 端 FUSE；与 MooseFS 同场测，并单列 P2P 传输和 Home 执行开销。
文件树冷启动索引先到、数据按需；小文件 pack 降对象与 RPC 个数；按启动 trace 预取常用路径，热 Blob 多源服务。到首个可运行命令时间、metadata bytes、实际读到的 data bytes、pack 放大、p95 首读与源节点带宽。
磁盘文件启动首版多源并行完整下载、传输块校验/断点续传；下载后本地直接供 Firecracker 使用。全量下载时间、每节点带宽、校验 CPU、启动并发；不把“文件树按需启动”收益套用到它。
发布与副本写者稳定切点之后异步转换/复制；同租户内内容复用与增量父版本候选要经真实命中率证实。切点暂停时间、后台完成时间、每版新增物理字节、两份副本达标时间、失败清理与 GC 成本。

旧 Home 预览版同场 W1 曾明显快于 MooseFS，但那是另一个分支、另一套验收条件；新 AFS 要重跑。实际 Agent 在 Home 的比例决定整体收益：若本地操作比例为 p，平均单操作成本可先用 p × 本地成本 + (1-p) × 远端成本 估算；真实尾延迟、并发干扰和任务完成时间不能这样线性推断，必须跑 Agent trace。镜像的冷启动与 fan-out 应单列测量，不能和 workspace 小文件 W1 混为同一性能排名。

09 · 借鉴开源项目，但不复制其目标

项目可借鉴的机制AFS 的取舍
（3FS）控制面/元数据/存储/客户端分层；副本与读源选择；FUSE 与 native 路径的开销分析。3FS 面向高吞吐集群、FoundationDB 元数据、RDMA 与文件等长 chunk/CRAQ。AFS 2–4 节点 Home 本地主路径不默认采用全局分片/链复制；镜像多副本只借其“可从多份读”的方向，发布规则另定。
（RustFS）S3 兼容对象存储的分层、持久对象接口和运维参考，可作为 Blob 后端候选。它不是 POSIX Home 现成替代；内建一套对象/纠删码集群会增加 2–4 节点运维与语义成本。先定义 Blob 存放接口，再用真实故障/成本测试决定是否接入。
（Nydus）metadata bootstrap 与内容 Blob 分开、内容摘要、按需范围读和预取。AFS 先针对 gVisor 文件树定义最小发布索引；可规划 Nydus/OCI 导入适配，但不声称当前 manifest 就是 RAFS 或必然使用 fscache。
（AgentENV）私有写层、快照工件的完整提交、P2P 在持久源之后加速分发。只借提交/分发边界；OverlayBD/ublk 或 VM 生命周期不强行成为 AFS 文件树模型。其 P2P 配置仍需按产品成熟度独立审查。
（E2B）不可变基础模板 + 沙箱私有写层、缓存/预取、控制与数据角色分离。AFS 只管文件/磁盘内容与版本；E2B 的内存恢复、编排流程和平台合同不自动属于 AFS。
（Firecracker）明确 VM state、memory 与 disk 文件分属不同工件，磁盘由宿主管理。首版磁盘文件全量下载到本地，配单沙箱独立可写层；块级按需读取和完整 VM 恢复另立需求与验收。
旧 AFS/DMS Home 预览本地文件、粗粒度归属、P2P 远端、FUSE inode/handle、故障收敛及 Linux W1/W2 证据。旧版另一远端后端仅留作历史证据。按新双 workload 合同逐块重用，不整目录拷贝旧状态机。具体本地证据见 需求证据。

10 · 实施切面与验证顺序

本轮只修订设计，不启动产品实现。下一阶段依次闭合：根与授权状态机 → 同 Worker 的本地文件路径 → 首次共享 ACK 屏障及 P2P → runtime 显式稳定切点 → 副本与原子发布 → 版本索引/P2P 读取与真实沙箱启动。每步都在 Linux 产生新的证据。

首先证明什么关键反例 / 指标通过才允许的优化
根解析与授权嵌套 mkdir 不多建根；A/B 并发创建；B 首读必须晚于 A ACK；旧世代、进程重启、通知重放。根路由与授权缓存；热路径 0 中心 RPC。
共享缓存与身份同一 workspace A/B 交替写、长短内容、同名重建、rename/unlink 后旧 FD；跨 namespace 的同名文件不能碰撞。只读 open 小内容同返；独享内容缓存另立门禁，不能默认开启。
运行时稳定切点多进程持续写、多文件 rename/delete、guest I/O；pause/cut/resume 中途退出；upper whiteout 和 base 依赖。reflink/COW 缩短停顿；后台并行构建，避免重复扫描未变内容。
发布与 MetaStore第二副本未完成、commit 丢回复、Master 换主、旧主恢复、pin/GC 并发；单/三节点能力分别验收。批量流与合并控制请求；共识仍只进粗粒度慢路径。
性能归因按 §05 RPC 预算追 trace；W1 同场 Native/薄 FUSE/MooseFS，镜像测切点暂停、完整发布、冷/热启动与 fan-out。收益成立后按总耗时占比优化；RPC 减少不直接推导吞吐倍数。

11 · 本轮三次自审

轮次发现的问题修订结果
1 · 抽象与用户 case把 DataHome 当独立进程；根归属未区分访问权；close 被误读为发布。新增语义章和模块表；同进程图；从父 inode 解析根、授权缓存、撤销 ACK 前后；运行时显式 RequestSnapshot。
2 · 故障与隔离双份手写控制日志与 Raft 目标冲突；根删除与缓存 grant 的生命周期不完整；暂存副本可能被过早回收。改成 etcd-first / 内嵌 Raft 候选，分别声明 1/3 节点；补删除/重建/中断对账；收据与保留责任绑定；两个 namespace 独立，同根共享另协调。
3 · 成本与证据“0 P2P 写入”漏了远端 base 首次 copy-up；容易把 3FS 每个 write 算成中心 RPC，或把批量流算成一个 RTT。明确本地化前提，单列 copy-up/物化旧内容的范围读；列 3FS 实际 create/open/flush/close 路径；RPC、流内消息、共识和 IPC 分账。静态 HTML/SVG/链接检查，不将其称作性能验证。

源码参考与设计预算不是运行证据。共享授权、稳定切点、镜像两副本、Master 后端和运行时接入均待新分支 Linux 实现验证。
