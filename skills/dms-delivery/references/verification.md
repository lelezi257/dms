# 验收与发布准备模板

## 一句话结论

能证明什么、不能证明什么。测试数、README 命令、制品清单和性能不是互相替代的证据。

| 验收项 | 命令/环境 | 实际结果与证据 | 未覆盖边界 |
| --- | --- | --- | --- |
| 正确性 | 待填写 | 待填写 | 待填写 |

按风险选择项：fmt/Clippy/unit/doctest、跨进程 bytes、SHM/缓存失效、超时与未知提交、WAL 再恢复、资源上界、观测开销。不是每个小修都运行全部集群测试，但需要解释省略理由。

性能比较保持环境与输入一致，给 p50/p99、错误数和原始样本；不靠 sleep 遮蔽一致性问题。内存指标区分 allocator charge、已隔离共享页与进程 RSS。

## 文档与开发规则

从全新用户入口走 README→环境→启动→API→界面。检查本地链接、参数默认值、实际 API 和限制；源码独立 checkout 不依赖外层笔记。Markdown/HTML 同源校验，diff baseline 必须人工已认可。

变更 skill 后用独立场景试用：给输入，不提前告诉期望答案；检查是否选对阶段、不过度生成产物、遵守边界。没有实际运行不能标成经过验证。

## 只有发布阶段才执行

区分源码 path 编译与发布包安装。SDK 要真实构包、隔离消费者编程；服务要真实安装/启动；`package --list` 不是发布成功。检查许可证、权利归属、依赖许可、敏感信息、版本与兼容说明。远端上传/tag/公开仓库需要本次授权，不用示例地址冒充已发布。

## 人工门禁

列少量剩余选择和风险，给唯一下一入口。结论通过之前不提升 baseline 或声称人工验收通过；后续阶段按用户确认推进。
