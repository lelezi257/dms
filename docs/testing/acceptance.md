# 测试与验收

本页定义当前有效的验收口径。历史原始证据和逐轮日志在仓库上一级 `local-archive/`；Git 历史仍保留原文件。

## 版本边界

- 历史结果只对原版本、原二进制、原环境和原判据成立。
- G1 历史 8/8 不重开；当前版本回归属于 G2。
- 新候选不能因为旧候选通过而自动继承结论。
- 功能通过、测量完成、性能改善和最终达标分开登记。

## 标准测试

POSIX 功能完整性优先参考标准套件，例如 pjdfstest、LTP filesystem 子集和短 FSx。标准套件通过是兜底项；项目自定义小用例只补充当前交付场景、恢复路径、权限和性能边界。

完整标准未跑或只跑 smoke 时，必须明确发现数、选中数、跳过/TODO、失败和版本身份。

## 当前 G2 验收顺序

1. OwnerFs workspace bind ON 必要功能闭环和试用交付。
2. OwnerFs 远端读写，以及 bind ON 与远端 FUSE 访问协同。
3. DFS 一写多读核心场景。
4. 普通 OwnerFs 本地 FUSE 访问和性能优化。

大规模、长时间、复杂可靠性、多 Meta、etcd 和 Redis 后置。

## 性能判据

- OwnerFs workspace bind mount：选定核心 case 接近 native ext4，沿用 `>=0.90` 判据。
- 普通 OwnerFs 本地、远端核心读写：吞吐 `>=1.2x` 同条件 MooseFS，独立操作时延 `<=0.8x` 同条件 MooseFS；两项都要满足。
- DFS：同接口、三同步持久副本条件下持平 3FS。
- 删除：先验正确性，并给出性能对照报告，不新增硬比例。

每个性能 case 开跑前固定接口、数据、并发、缓存、持久屏障、副本语义、计时边界和判定分位数。记录操作时延 p50/p95/p99，并在开跑前固定用于判定的分位数。吞吐和时延分别测量，不从吞吐反推时延。

## 运行环境

Rust 构建和文件系统测试只在 Linux 执行。macOS 仅用于编辑和 VM 编排。测试前一次性检查依赖、套件版本、二进制身份、挂载和容量；遇到真实环境阻塞时保存证据，停止受影响项，继续独立任务。

维护中的验收驱动位于 `tests/acceptance/`，测试辅助程序位于 `tests/support/`。普通试用包不包含测试探针。
