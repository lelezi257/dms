# 实现阶段模板

## 输入与本批边界

引用已确认设计和接口。列目标文件/模块、不能改变的行为、本批实际交付（骨架、Mock、真实实现或部署链路）；不要把不同完成度混在一起。

## 开发顺序

接口仍未确定时，先用原生 Rust 定义业务服务合同；protobuf 只处理 wire，明确 Mock 的状态、错误、顺序和故障语义。已有确认接口不要因写实现而重新发明名字。

重构先锁行为回归，再小批修改。围绕用户用例从 SDK 到服务验证，不仅逐模块填函数。一个批次说明代码入口、核心算法、生命周期与异常处理；中文注释解释原因和保证，不逐行翻译 Rust。

## 验收项

写本批新增/保留的测试及真实 E2E 命令。环境与业务测试先后明确，不能运行则披露而非换宿主机。协议、错误、metrics、日志、trace 按源码规则接入，只覆盖真实存在的功能，不先制造空数据。

## 交付给人看

按“改变的行为/抽象—为什么—关键文件—证据”总结。有全局影响的调整一起检查调用方、协议、Mock、示例、文档，不做只修最后一行的补丁。阶段结束等待本次计划约定的 review，不自动升级为发布任务。
