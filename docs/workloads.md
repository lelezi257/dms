# 两类工作负载的语义边界

本文速览已确定的用户目标，不声称已经实现。完整 case、故障与验收语义以 [需求分析](requirements.html) 为准；实现思路见 [详细架构](architecture.html)，具体协议与性能仍待穿刺。

## Agent workspace

- 用户通过统一目录操作文件。一个工作目录通常有主要运行节点；Master 能查询 Home，调度器可据此做亲和调度。
- WorkspaceRoot 是根目录授权单位，子目录继承 RootId；首次获取 Master 的 RootGrant，后续复用。B 首次访问先等 A 撤销独享、完成屏障并 ACK，Master 提交新授权后才放行。
- 主要节点上的读写以本机普通文件为基础，避免每个操作远端提交。别的节点也能通过 P2P 直连 Home 访问同一个 workspace，必须支持正确的多读多写；跨节点共享可慢于本地主路径。
- 用户需要明确成功写入、重新打开、fsync、并发访问与故障后的可见性和耐久边界。旧分支的具体合同不自动继承，详细设计须逐项选定并验证。

## 镜像与快照

- Agent 可以持续写私有 upper；由沙箱运行时显式发起快照，close/fsync 不自动发布。稳定切点与原子发布是不同完成状态；必须保存 upper 与 base/whiteout 的合成语义。
- 一个待发布版本只有自己的写者能看到。写者完成稳定快照后，系统校验必要元数据与数据，再一次性发布固定版本；失败的版本不可供读者打开。
- 已发布版本不可覆盖或原地修改，可由多个节点同时读取；不同写者可以分别产生新版本。版本需要可校验的身份和足够的持久副本；缓存、预取和 P2P 只是加速，不能冒充耐久承诺。
- gVisor 可消费文件树；Firecracker 可消费一个完整下载到本地的磁盘镜像文件。两种产物共用版本、存放与分发后端，但呈现给运行时的方式不同。沙箱后续写入属于自己的私有写层，下一次发布形成新版本。
- 文件内容快照不自动包含运行中进程的内存和设备状态；如需继续原进程执行，必须另行设计该部分。

## 共同边界

每节点一个 AFS Worker 进程承载 FUSE 与两后端，Home 仅是数据所在节点。两类 namespace 及其授权视图隔离，互不可见文件；同一个 workspace 在不同节点访问仍需共享协调。两类目录在 FUSE 根入口显式区分，不能跨后端静默改名、硬链接或借用对方的写入语义。Master 的职责限于粗粒度归属、版本和位置；数据操作在 worker 与其后端完成。

近计算与 P2P 是共同架构特征：Worker 与计算节点共置，调度优先利用 Home 和已有镜像副本/缓存；Master 提供位置查询，文件内容由节点直接传输。产品不保留 NFS 后端。Workspace 的远端共享不转换 Blob，显式镜像/快照发布才进入不可变表示。

Master 权威后端先采用 etcd，后续可换成内嵌 Rust Raft；接口承诺条件事务、权威读、持久提交和恢复。单节点与三节点多数派模式分别声明容错，控制面副本不等于 workspace 数据副本。
