# MetaStore 提交边界（2026-09-27）

**决策。** `Meta`/`owner_roots` 负责节点会话、根归属和授权的业务命令；`meta/rpc.rs` 只做身份、协议和错误转换。`src/meta/store.rs` 是业务命令使用的权威状态入口：条件检查、请求去重、逻辑 revision、watch 和恢复扫描都在同一份已提交状态上完成。后端只保存/取回完整且带版本的状态字节，不理解 RootGrant 或 NodeSession。

一个请求进入 Store 队列后，Store 在私有副本里执行；短暂收集窗口最多合并 64 个操作。若有实际变更，它将实体、请求结果、节点会话围栏和 watch 历史作为一个状态提交给后端。**后端确认以前，新状态不可读，也不回复成功；确认以后整体发布，再回复这批请求。** 后端提交失败时，本进程拒绝继续提供权威读写，重启时从后端重新加载，避免不确定提交后继续签发旧授权。条件不满足或无效请求不会产生物理提交。一个批次中的各操作仍有独立、递增的逻辑 revision。

后端及边界：

| 配置 | 当前作用 | 故障边界 |
| --- | --- | --- |
| `etcd`（默认） | 单键 CAS 状态提交，键为 `/afs/meta/snapshot` | 需要部署保证单活动 Meta；CAS 可发现竞争提交并让失败方拒绝继续服务，但不等于完整选主 |
| `local-file` | 本机 WAL、同步落盘和进程排他锁；运行目录为 Meta `data_dir/meta-store` | 单机/单盘持久；不能把此模式称为跨机器高可用 |
| `memory` | 易失内存后端 | 仅全新、可丢弃的开发测试；Meta 退出即丢失权威 |

**现阶段不做 Meta 选主。** `etcd` 后端仍必须由部署保证单活动实例；本轮的 CAS 会检测竞争写并让失败方拒绝继续服务，但无法在尚未发起写时发现另一个活动实例，因此不能把它当成双 Meta 自动故障切换方案。

**Node 边界。** 当前 FUSE 和 OwnerFiles P2P Handler 已将业务请求交给同一份 OwnerFs 文件/句柄状态；RPC 负责认证和 Proto 转换，不需恢复 actor，也不为移动适配器新建核心层。SDK 的 OwnerFs 业务入口留白，待 BlobFs SDK 语义设计时再决定。本轮不改 OwnerFs 热路径或已测 W1/W2 数字。

**待验证与规模限制。** Store 状态目前包含完整实体、去重结果和 watch 事件；每次物理提交重写全量字节。它只承接粗粒度控制面，不能在未测量容量和提交延迟前宣称适合无限历史或每文件写入。后续应明确 watch 压缩及请求结果保留策略，再做大规模性能验收。跨进程多主安全、选主和真实故障注入另立设计与验证。
