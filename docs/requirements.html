AFS · 产品需求合同 · 2026-09-25

两种工作负载，两个明确的承诺

AFS 服务 Agent 的可写工作目录，也服务写完即冻结、供大量沙箱读取的镜像与快照。它们共用路径入口和集群控制，却不共用文件更新语义。

状态：架构设计输入；不是当前实现能力。依据：已确定的 AFS 宪法、工作负载边界，以及本页末尾的源码和开源项目证据。
详细架构设计 →Workspace镜像 / 快照共同合同验收
主场景

2–4 节点；多数 Agent 在自己 workspace 的 Home 节点连续读写，调度器能查询 Home 并维持亲和。

第二场景

单写者在私有区生成稳定版本；发布后不变，许多 gVisor / Firecracker 沙箱跨节点读取。

首版边界

常用文件操作、明确故障结果与同场性能证据；不以完整通用 POSIX 或长稳发布为门槛。

01 · 如何读这份合同

已决方向 来自用户确定的两类 workload 与 宪法；设计选定 是本轮为端到端闭合而定的具体语义，实施前可用新证据修订；待验证 需要 Linux 端到端测试或实际 Agent 采样。性能目标是工程门槛，不是本分支已经取得的数字。

统一的根路径只是用户接口。/workspaces/<id>、/images/drafts/<id>（仅写者可见）和 /images/versions/<id>（发布后只读）是本文示意命名；业务后端彼此独立。跨类型改名、硬链接或把已发布版本原地变为可写文件，首版明确拒绝。

02 · Agent workspace：频繁可写，位置尽量稳定

已决方向 一个 workspace 属于一个 Home 节点。Agent 通常也在 Home 运行；本地文件就是权威数据。Agent 因 CPU / 内存压力移到其他节点时，workspace 仍留在原 Home，先接受远程访问成本，调度器可在条件改善后把 Agent 调回。确有跨节点共享时，所有节点访问同一份 Home 文件，不在各节点生成各自可写副本。

谁在用

Agent 进程通过 POSIX 路径进行编译、编辑、日志、依赖安装和工具调用；管理面创建、删除、定位 workspace；调度器查询 Home 后选择运行节点。

价值假设

本地热路径只有一次 FUSE 入口与本机文件操作，不要求每个文件写同步找中心、转换 Block 或发布分布式版本。相对默认 MooseFS 的优势必须在真实相似用例上验证。

用户能观察到的关键 case

Case操作与期望必须补齐的边界
W0 创建 / 定位管理面或 POSIX 首次创建一级 workspace；Master 确定 Home，返回可查询的位置，调度器据此做亲和。两个节点并发建同名根目录只成功一次；Home 文件树与 Master 归属不分叉。
W1 本地常态Agent 在 Home 内创建、打开、随机/追加写、读、改名、删除、截断、列目录、同步；普通写不等待中心。本机文件的成功字节数、失败后已写部分与 fsync 语义按 Linux 文件系统报告，不能虚报整笔成功。
W2 迁走计算Agent 在 B 继续访问 A 的 Home；读写真正执行于 A，管理面仍报告 Home=A。远端断线、超时、重试与未知结果不能把一次非幂等操作当成两次成功。
W3 跨节点共享A、B 可同时打开同一目录；一个进程完成写入并关闭后，另一节点重新打开能看到新内容。旧页缓存、属性缓存和负目录项不能让重开读取旧版本；正在并发读写的字节级结果另按普通文件语义处理。
W4 删除 / 重建删除文件后旧打开句柄仍指原文件；同名新文件有新身份。跨 workspace 根目录移动明确返回 EXDEV。不能让旧句柄错改新文件，也不能复用旧根目录的路由世代。
W5 故障 / 重启Home 进程或前端 FUSE daemon 重启后，重新挂载、重新打开可以恢复；Home 整机失联期间返回不可用，恢复后重新访问。运行中的旧 FD 不承诺无感续接；Master 不能在旧 Home 仍可能写时另授予新 Home。

首版操作覆盖（需求，不代表已实现）

级别需要覆盖的接口验收重点
必须路径查找、stat/readdir、mkdir/rmdir、create/open/close、read/write、append/truncate、rename/unlink、symlink/readlink、同一 workspace 内 hard link、chmod/权限检查、fsync/fdatasync。Agent 工具链常用文件树能工作；改名/删除后旧 FD 保持原身份，跨节点重开可见；权限、错误码和短写准确。
需要专项证明跨节点 flock/fcntl advisory lock、可写 mmap、xattr（包括 Linux capabilities）、稀疏文件/fallocate、目录 fsync、配额。先对真实 Agent / 容器工作负载采样；若无法在首版正确实现，显式标为不支持或限定本地使用，不能静默返回成功。作为适配门槛的操作必须在同事试用前完成。
不承诺跨 workspace 原子 rename/link、FUSE daemon 重启后旧 FD 无感续接、Home 永久丢盘后的透明故障接管。跨根操作返回 EXDEV 或明确错误；应用可以重挂载、重新打开并重试。

首版一致性与耐久约定

设计选定 同一 Home 对目录和文件修改负责。远端共享以 close-to-open 为可检验边界：写者成功完成写入并关闭后，读者下一次打开必须重新验证；fsync 成功意味着 Home 底层文件系统已经确认同步，不意味着另一个物理节点已有副本。进程复用已经打开的句柄时，跨节点并发修改的细粒度顺序不承诺分布式强一致；需要字节级同步的应用自行使用其锁协议。跨节点 flock/fcntl 等专项接口按上表先证明或明确拒绝，不默默假装生效。

故障域 本地普通写按 Linux 返回字节数确认，fsync 后才宣称已按底层文件系统合同落盘；未同步字节在 VM/磁盘故障后可能丢失。单 Home / 单数据副本不提供 Home 永久磁盘丢失后的恢复，也不提供 Home 离线时跨节点接管。若以后增加数据副本或零中断接管，属于另一套成本与验收合同。

POSIX 范围 首版以本节操作表为最低覆盖，逐项列出错误码和平台约束。普通文件作为事实源不等于 FUSE/P2P 自动支持对应回调；旧 Home 预览版就缺少数项回调与权限恢复用例，详见 本地白盒证据。

03 · 镜像与快照：私有写、一次发布、只读多点

已决方向 工作中的可写层属于单个沙箱或构建者，只对该写者可见。完成一个稳定切点后，后台可压缩、合并小文件、复制和校验；只有完整发布后，读者才按固定版本访问。新写入在新的私有层，形成下一版本，不回写旧版本。该目标与 Agent workspace 的原地改写不同。

gVisor：文件树

运行时需要目录/文件元信息以尽快启动，内容可按需读取。已发布文件树可通过共同 FUSE 呈现；冷启动时优先取得索引，随后只拉取实际访问的内容范围。按需读取是设计目标，具体 gVisor 接入性能还需 Linux 实测。（Nydus）

Firecracker：磁盘文件

首版把固定版本的大磁盘镜像完整、校验后放到本地文件，再作为 VMM 块设备后端；启动后的读写路径不必须经过 AFS FUSE。新的写入应进入该沙箱独立可写层，形成快照前不影响基础镜像。（Firecracker）

用户能观察到的关键 case

Case操作与期望必须补齐的边界
I0 私有构建构建者通过同一 FUSE 入口的私有 draft 路径独占写入文件树或磁盘文件；其他人按路径/版本名看不到半成品。可写层使用本机普通文件而不是已发布 Blob；只有授权写者可访问，进程故障可清理或恢复自己的 draft，不泄露给读者。
I1 稳定切点写者暂停或通过文件系统快照取得稳定视图，随后可继续写新的私有层；后台转换旧视图。不能一边遍历活跃目录一边宣称得到原子快照；无 reflink/COW 能力时必须选择暂停复制等慢路径。
I2 发布内容及索引校验，达到规定的跨物理节点耐久副本数后，一次性公布版本身份；失败不暴露版本。发布超时可按请求身份查询结果；重复发布不可产生不一致的两个版本。
I3 多点读很多节点同时读取同一版本；来源可为持久副本，也可为经过校验的缓存/P2P 节点。缓存失效、源节点断开时换源，按内容校验，不允许“返回部分旧版+部分新版”。
I4 启动与新写gVisor 见已发布文件树并写私有上层；Firecracker 从验证完整的本地磁盘文件启动并写自己的差分层。文件系统镜像只负责磁盘/文件内容。运行中的内存、设备状态若要恢复，是独立工件和接口。
I5 回收删除一个版本别名后，已在使用它的读者仍可完成当前读；最终回收未引用数据。版本固定身份、引用/保留期与垃圾回收不得竞态删除活跃读者所需 Blob。

设计选定 “多副本”默认指至少两个不同物理节点的持久副本，并把副本域显式记录在版本中；单个节点上的两个目录不算两份。首版在仅两节点时，少于两份不能宣称发布成功；若运维允许降低副本数，必须创建可见的低耐久策略而非静默降级。缓存节点和 P2P 中转节点不计入副本数。已发布版本的 manifest 与提交记录也必须在至少两个不同物理节点持久可恢复，不能让 Master 单盘成为整版消失的唯一故障点；Master 服务本身首版仍可单主、故障时暂停新发布。高并发启动时优先从副本和已验证缓存读取；源节点/缓存选择策略不改变版本内容。

“快照”在本文默认是文件或磁盘内容快照。Firecracker 的 VM 状态、内存、设备快照有自己的工件和恢复规则，AFS 不把一个磁盘文件误称为可恢复运行进程的完整 VM 快照。（Firecracker；E2B）

04 · 两类业务共用的外部合同

主题需求首版明确不承诺
入口与命名空间每 worker 一个 FUSE daemon 和一个可见挂载根；根下按类型路由。Master 对 workspace Home 与已发布版本提供管理面查询。跨后端原子 rename/link、以通用对象 API 写版本。
权威与分区Master 持久保存 workspace 与私有 draft 的粗粒度归属/世代、版本目录和副本位置；已确认的根目录/版本控制记录跨两个故障域可恢复，数据读写不逐次找 Master。丢失 Master 时已有本地 Home 与已知不可变版本可按安全条件继续；创建、迁移、发布暂停。网络分区时自动选第二个 Home、无围栏的故障切换。
安全与隔离挂载路径不能越过 workspace/版本根；身份、权限、跨节点传输认证、租户范围、版本校验应可审计。为性能合并小文件不能跨租户泄露内容。因 P2P 可达就信任对端返回的未经校验数据。
运维与可观测暴露 Home 命中率、FUSE 调用、元数据与数据阶段耗时、P2P/NFS 请求、缓存命中与失效、发布队列、副本不足、源切换、GC 和失败原因。只给单一 E2E 数字而无法归因。
部署2–4 节点 Linux；提供源码构建与安装包路径。具体内核、FUSE、NFS/文件句柄、快照、磁盘要求在实现时明示并探测。所有内核/文件系统能力天然存在。

05 · 验收以可观察行为为准

维度验收输入与指标判定方式
Workspace 功能W0–W5，至少 2 节点，再覆盖 4 节点；文件内容、errno、旧句柄、同名重建、close-to-open、fsync。每个承诺有 Linux 真 FUSE E2E；未支持操作列在兼容表，不以“编译通过”代替。
Workspace 性能本地小文件/元数据密集 W1、预建目录内操作、迁走计算 W2、跨节点共享 W3；同场 Native、薄 FUSE、默认 MooseFS；报告 p50/p95/p99、样本、耐久/缓存差异及 Home 命中率。沿用此前已认可的本地优势场景 W1 p50 至少快 MooseFS 20%作为工程目标；并报告距 Native/薄 FUSE 的剩余成本。新分支必须重测，旧证据不可替代验收。共享路径要求功能成立且退化可解释，不假定优于 MooseFS。
镜像功能I0–I5；发布前不可见、稳定切点、失败不暴露、重复请求、两节点持久副本、损坏检测、读者在删除时继续、gVisor 与 Firecracker 两种消费入口。每条有端到端和故障注入证据；发布之后旧版本校验和不变。
镜像性能文件树冷启动首次打开/可运行时间、总拉取字节、远端范围读延迟；Firecracker 全量下载完成时间；1→N 沙箱并发启动时源节点流量与缓存命中。与直接全量复制、单源拉取和可用行业基线同场比较；先记录不改变正确性的基线，再按实际瓶颈定量化门槛，不凭架构推导宣称领先。
故障FUSE、Home、Master、发布写者、持久副本、缓存节点在关键切点故障。按预期继续/拒绝/重试，绝不出现双 Home、半发布版本或错内容；明确恢复时间与人工动作。

W1 20% 是旧阶段用户认可的工程价值门槛，新的 AFS 设计把它保留为待验证目标；耐久条件不一致时并列报告，不把不同语义的对照包装为等价排名。

06 · 证据与借鉴边界

旧 Home 实现白盒显示：其 Home 路径把文件放在本机文件系统，中心管理一级根归属，远端有 NFS/P2P 两种路径；新分支当前没有这些代码。阶段报告的两份 W1 六轮 DMS/MooseFS 中位耗时为 234/625 与 240/630 ms；这只支持旧预览版在特定本地 W1 的收益，不能代表新 AFS、完整 POSIX 或镜像后端。旧 Home 仍缺符号链接、硬链接、xattr、fallocate 等回调，旧 FD 在 daemon 重启时不能透明续接。证据：旧 Home 进程入口、根归属、本地文件路径、P2P 读写及旧阶段测量。

镜像侧已有单 VM Nydus、EROFS、OverlayBD/ublk、Firecracker、gVisor 的机制实验，但没有 AFS 自己的镜像服务、多节点 P2P 发布或真实沙箱规模性能；证据见本研究区 本研究区单 VM 实验记录（本地相对链接）。开源借鉴的具体取舍集中写在 架构设计的参考矩阵。
