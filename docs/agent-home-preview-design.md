# Agent workspace 节点归属文件系统：同事测试版设计

状态：2026-09-24 已对齐的目标与实施合同；实现与验证结果须另行记录。基点 `main`=`b36f570`。Native FS 只作参考，不作验收指标。

## 用户流程和边界

每台 Linux 节点启动一个公共 FUSE 挂载、home 文件服务和可选 NFS server。单中心持久保存 `一级目录 → home 节点`，管理面提供按目录查询与列表，供调度器亲和调度。节点注册公布数据地址。普通 `mkdir /job-42` 默认选择发起节点；预指定 home 的管理接口留作后续扩展，不属于当前实现。已有一级目录之下的所有文件和子目录都在同一 home 的本机目录中。

Agent 在 home A 的 `/job-42` 创建、修改、读文件：A 的 FUSE 查一次目录归属，此后对本机普通文件执行相应调用。B 打开该文件：B 查询 home、通过安装时选择的 NFS 挂载或 P2P 文件 RPC 访问 A 的同一份普通文件。B 的 FUSE 管理其本地 inode/handle；P2P 把实际文件操作交给 A，不请求中心逐文件提交。NFS 与 P2P 的权限、可见性及失败边界须由相同 E2E 验证，不允许“后端不同就悄悄变语义”。

## 控制与故障

中心写入归属的 durable record 后才对外宣称目录就绪。创建/删除应有可恢复的中间态或幂等修复，不能出现中心与物理目录永久分叉。注册信息是易失的，重启后节点重报；归属和 generation 持久。中心断连时禁止新归属和迁移；已有 home 可服务已知目录，但不能产生另一个写入 home。home 进程重启从普通文件恢复，不依赖逐写 Block/WAL；VM 故障期间该 home 的目录报不可用，原 VM 回来后恢复。首版不自动迁移 home。

当前删除会留下持久 tombstone；为防止其它节点的旧归属缓存误写，**一级目录名删除后不能复用**。这限制了常见工作区目录的复用能力，必须在同事测试中明确；后续需要 generation 围栏及缓存失效才能解除。中心 RPC 的变更命令和 P2P 文件连接使用共享 token，但传输未加密，也没有按节点划分权限；只能放在受信任私网，不能直接暴露到不受信任网络。

本轮共享语义采用 close-to-open：写者关闭并完成保存后，另一节点下一次打开必须看到新内容。`fsync` 成功表示 home 的本机文件达到约定的持久保存点。P2P 不可只比较文件时间戳判定跨节点缓存有效；NFS 使用保守挂载/缓存设置。首版为稳妥起见可以禁用远端持久页缓存；本地缓存只有在撤销及失效协议证明后才能启用。旧 FD 并发期间不承诺快照，冲突由 home 本机文件系统顺序裁决；不能静默返回旧内容冒充新打开结果。跨一级目录 rename 返回 `EXDEV`。NFS 选择 `hard` 以避免 `soft` 超时可能造成的静默数据损坏；代价是已进入内核 NFS 的操作在 home 失联时可能等待恢复，而 P2P 按显式超时失败。这一差异必须在故障测试和安装文档中明示，不能声称两者故障时延等价（[Linux nfs(5)](https://man7.org/linux/man-pages/man5/nfs.5.html)）。

P2P wire v3 在连接鉴权时检查协议版本。只读打开不超过 4 KiB 的文件时，home 可以把文件内容随 `OPEN` 一起返回，仅供这次已打开的 FD 使用；下一次 `OPEN` 仍向 home 请求，不能跨打开复用旧内容。P2P 只对已确认存在的名字缓存目录项。独享 home 的本地文件属性和公共挂载根目录属性有 1 秒内核缓存；第一次远端路径操作须先通知 home 的 FUSE 内核撤销已分配 inode 的属性缓存，此后该目录的属性 TTL 为零。本地属性读取和回复与这次撤销串行；远端路径操作在撤销完成后才执行。远端删除、改写后的 `stat` 和新打开继续向 home 验证；不跨 FD 保留页缓存。只读 FD 的释放沿同一 TCP 连接按序发送，不等待无数据修改的释放回复；后续 RPC 在 home 处理完释放后才回复。写入关闭和显式 `fsync` 仍等待 home 的保存结果。home 失联后，新打开必须失败；失联前已打开的只读 FD 可能读出随 `OPEN` 收到的内容，这不代表 home 可用。已经成功同步且之后未再写的 FD，关闭时不重复同步。
