AFS · 详细架构设计 · 2026-09-25

一个入口，两条数据路径

Workspace 让多数操作停留在 Agent 所在节点的普通文件系统；镜像先在私有层生成稳定版本，再把可校验的不可变内容分散到多个持久节点。Master 只决定粗粒度归属与发布，不逐文件代理数据流。控制记录在两节点持久镜像，避免版本的元数据只存一盘。

设计状态：可供实施拆解与风险穿刺的架构方案，不等于已实现。需求权威见 需求分析，边界宪法见 PRINCIPLES.md。

Home 事实源

Workspace 的目录与文件是 Home 上的普通文件；Master 只保存一级根目录归属和世代。

版本事实源

镜像版本是已提交的不可变 manifest + 已校验的持久 Blob；缓存只加速读取。

共同边界

一个 FUSE 挂载负责路由和 inode/句柄接入；两个后端自己管理语义，不造通用可写对象核心。

01 · 已收敛的架构取舍

选择采用理由付出的代价 / 不做的事
每节点一套 AFS worker/FUSE，路径分派POSIX 程序无需 SDK；同一根下暴露两种业务。FUSE 只转换调用与路由，不掌握业务事实。本地 workspace 仍有 FUSE 固定开销；旧 FD 在 daemon 崩溃后无法自动移到新挂载。
Workspace 单 Home + native 文件主 workload 的写回、改名、目录遍历无需逐次中心提交；可复用本机 FS 的数据/目录/恢复机制。Home VM 离线时该 workspace 不可用；首版不自动搬迁所有权或复制全部数据。
远端 P2P 为主，NFS 为可选后端P2P 保留传输可控和无需内核 NFS 的部署路径；NFS 借助成熟内核客户端作为可选对照与退路。P2P 必须补齐身份、未知结果、缓存、权限和错误语义；NFS 不能凭配置开关继承 P2P 的性能结论。
镜像独立不可变 Blob/manifest 后端只读多点、内容校验、去重与小文件聚合适合发布后版本，不强迫 Home 的每次写变成 Blob。发布前必须取得稳定切点；转换、复制和首读可能慢，放到镜像的慢路径。
Master 管粗粒度权威只承载 root 所属、epoch、已发布版本与副本位置、管理面查询。Master 故障时不能安全地创建/迁移 root 或发布新版本；控制记录须跨两个节点持久镜像，但首版没有自动控制面 HA。
性能原则：将不影响当前请求正确性的准备、压缩、复制、预取和回收异步化；不可把发布所需的持久副本、首次共享所需的缓存收敛、或本次 fsync 所需的本地同步挪到成功 ACK 之后。

02 · 组件、权威与交互关系

实线为数据路径，虚线为低频控制路径。图只画 A/B；同一部署扩展到 2–4 worker。Firecracker 启动后可直接使用已完整下载的本地镜像文件，不要求其每次块 I/O 穿过 AFS FUSE。

模块归属

组件 / 模块唯一权威或职责不得拥有
AFS FUSE / RootRouter一个 mount 的 inode/handle 映射、请求适配和类型分派；重启时根据 Master/后端重建可查状态。持久的 workspace 文件真相、不可变版本的提交状态。
Master / RootCatalogWorkspace 一级根归属、epoch、创建/删除状态、节点端点与管理面 Home 查询；成功的根变更记录同步镜像到另一故障域。逐文件 inode、逐写 WAL、逐读转发。
WorkspaceHome本机普通文件、路径内操作、文件身份、共享时本机缓存收敛。把每次写强制转成不可变 Blob。
WorkspaceRemote根据 root owner 转发到 Home；P2P RPC 的请求身份/结果未知处理，或可选 NFS adapter。第二份可写目录树或与 Home 竞争的本地元数据事实源。
ImageDraft / ImagePublisher / ImageReaderDraft 在同一 FUSE 下为单写者提供私有本机文件树或磁盘文件；Publisher 从稳定视图生成索引/Blob、复制、校验和提交；Reader 按固定版本寻址、校验与回源。改写已发布版本；以缓存冒充持久副本。
Master / DraftCatalog + VersionCatalog + Placement私有 draft 的写者/归属节点与状态；版本/别名原子提交、发布状态、耐久副本位置与引用保留。控制记录与已发布 manifest 同步留在两个故障域。逐范围读取或镜像数据字节。
Common 工具鉴权、传输连接、指标/追踪、校验和可共用的本机 I/O 工具；只在双方真正复用时抽取。统一两类业务语义的 Object/Block 状态机。

FUSE inode 是当前挂载的内核标识，不是存储权威。将后端类型、root/version 身份、epoch 与本地文件身份映射到 FUSE inode；daemon 重启后可由路径查询和已发布 manifest 重新建立映射。旧 FD 属于旧挂载，不宣称透明续接。旧 Home 预览版的远端本地 inode/handle 表与不透明文件句柄提供实现线索，但需要按新合同重新审查：其旧路径保护禁止跟随符号链接，而新需求要求 symlink/readlink，须在不允许 Home 端路径逃逸的前提下实现。（本地旧代码：source-agent-home-preview/server/homefs/src/home_fuse.rs、file_identity.rs）

03 · 数据模型：只在需要之处引入 Blob

WorkspaceHome：文件就是文件

WorkspaceRoot = {id, home, epoch, state} 只定位一级根。镜像私有 Draft = {id, writer, home, epoch, state} 也只需粗粒度定位，draft 内容在该节点的普通文件中；两个后端的业务状态机仍独立。其下 inode、dentry、内容由 Home 的本机文件系统管理。AFS 仍要保存根创建/删除与 epoch 的最小控制事实；不为普通写建立逐回调 Block、Extent 或中心版本指针。

Image：版本是不可变索引

SnapshotVersion = {id, kind, parent?, manifest, replica policy, state}。kind 明确文件树或磁盘文件；manifest 固定目录/文件属性（类型、权限、uid/gid、时间、链接和必要 xattr）、范围映射、大小和内容摘要；磁盘文件则按不透明字节镜像编目。发布后只允许添加新的版本引用，不更改旧版本内容。

Blob、Extent、Chunk 的准确含义

抽象在 AFS 中的作用是否进入 workspace 主写路径
Blob已封存、带内容摘要的物理不可变字节对象；可由多个节点持久保存，也可被本地缓存。小文件可打包进同一 Blob。否。只有快照发布的后台转换才产生 Blob。
Extent / 范围映射manifest 内的逻辑文件偏移 → Blob 偏移与长度，用于已发布文件树按需读；磁盘文件可简化为大 Blob 的连续范围。否。不是 workspace 每次改写时的版本布局。
Transfer chunk大 Blob 网络传输、并发拉取、断点续传与分段校验的单位；大小可由压测选择，不必等于文件系统 block。否。它不改变 POSIX 文件身份。

设计选定 首版版本索引只覆盖已确定的文件树/磁盘文件读取需求，不设计任意读写通用分布式 POSIX。索引可保留导入 OCI/Nydus 工件的适配空间，但不把 RAFS 格式或 RustFS 对象接口直接当作 AFS 的业务语义。按需读取的索引/数据分离与小块校验借鉴 Nydus；Blob 存储可使用 AFS worker 的本地副本，未来也可接外部对象服务，必须先核对 2–4 节点成本与耐久语义。（Nydus；RustFS）

04 · 关键端到端时序

A. 创建目录 → Home 本地读写

  1. 节点 A 的应用执行 mkdir /workspaces/job-42。A 的 FUSE RootRouter 只识别这是新 workspace 根，向 Master 申请带唯一请求号的归属；Master 根据放置策略选择 A 或另一节点，把 PREPARING + epoch 控制记录同步持久化到两个故障域。应用可在管理面查询 Home，调度器据此放置 Agent。
  2. 被选中的 Home 在自己的本机文件系统准备该目录，保证根名不会越界，并按创建合同同步必要的目录控制事实；Master 再把 ACTIVE 控制记录同步持久化到两个故障域后回应成功。任何中途重启均按请求号与状态收敛，不允许两个 Home 都生效。
  3. Agent 在 Home 打开 /workspaces/job-42/src/a.rs。FUSE 根据一级根定位到本地 WorkspaceHome，后续 create/write/read/rename 直接落在普通文件和本机 FD；Master 不参加每个文件操作。fsync 下沉到本机文件系统。

B. Agent 换节点 / 两节点共享

  1. Agent 从 A 暂停后在 B 恢复。B FUSE 从缓存或 Master 得知 job-42 → A, epoch=e；B 的 WorkspaceRemote 在本地维护本次挂载的 FUSE inode/handle 映射，经 P2P 以 root epoch 与文件身份把操作发给 A 的 WorkspaceHome；这不是简单复制原始 syscall 字节。可选配置用预挂载 NFS 代替 P2P。Agent 位置改变不等于 Home 数据迁移。
  2. B 第一次参与共享，或 A/B 同时访问时，Home 使目录进入保守共享访问规则：切换前清理有关的 FUSE 内容/属性缓存和负目录项；远端打开重新验证，远端读避免不受控页缓存。已开句柄的可见性仍按 close-to-open 合同处理，不承诺逐字节同步快照。
  3. B 的修改在 A 执行。写者完成写入并关闭时，Home 完成必要的本机写入/同步边界与失效通知；A/B 下一次打开读取到已确认内容。失效链路不可用时，改走无缓存校验或拒绝成功，不以“稍后 TTL 到期”满足重新打开语义。
  4. 断线后 B 不盲重放 O_TRUNC、append、rename、unlink 等非幂等请求；用请求身份向 A 查询结果；对无法证明未执行或已执行的操作，返回结果未知对应的 I/O 错误，要求应用读取当前状态后决定是否重试，绝不由 B 自动重放。若要给非幂等操作提供透明重试，需在远端慢路径增加可恢复操作收据并证明与文件变更的切点一致；不能只靠 RPC request ID 假装 exactly-once。旧句柄身份不再可信时明确 ESTALE，应用重新打开。
“共享模式”是目录的缓存与路由状态，不是把目录里的所有文件一次转成 Blob。可以异步预热目录或登记已有文件，但首次远端访问只等待本次正确性必需的失效/定位。恢复独享模式须确认其他访问者已离开并撤销其缓存授权；不能靠固定时间猜测。

C. 镜像生成 → 发布 → 多点启动

  1. 写者先经 Master 创建带写者身份和归属节点的私有 draft；之后经共同 FUSE 的 /images/drafts/<id> 在该节点的本机文件中准备文件树或磁盘文件。Master 不参加 draft 的逐文件写入；从 workspace 取快照是另一个显式导入入口，不能偷偷把活跃 workspace 变成镜像。发布请求首先形成稳定切点：暂停写者并建立本机 reflink/快照，或在无此能力时暂停复制。切点完成后，写者可继续写下一私有层。
  2. 后台扫描稳定视图，生成文件树 metadata index，合并适合的小文件，对大文件建立范围/传输块索引并计算摘要。把 Blob 和 index 写到至少两个不同物理节点的持久存储，校验每个副本；这一步异步于写者继续工作，却先于版本发布。
  3. ImagePublisher 把固定 manifest 与副本证明提交到 Master 的 VersionCatalog。Master 作为唯一提交者，先把带请求号、manifest 摘要、别名条件更新和顺序号的提交决定同步写入两个故障域，再使版本从 PREPARING 变成 PUBLISHED 并 ACK；失败或副本不足则不让读者打开。中途失联后的结果可按请求号恢复为成功或失败，不靠客户端猜测。别名更新可指向新版本，但已发布旧版本 ID 不变。
  4. gVisor 节点先获取目录/文件索引，再按实际访问的范围向持久副本或已校验缓存节点读取。Firecracker 节点完整下载并校验磁盘文件，随后把本地只读基础镜像和独立可写层交给沙箱；首版不要求块级远端懒加载。下一个快照重复稳定切点与发布流程。

D. 删除与恢复

  1. 删除 workspace 根先阻止新的打开和归属分配，再处理在用句柄与 Home 文件树，最后持久化墓碑；与同名重建使用新 epoch。删除已发布镜像只撤销别名或增加墓碑，不立即删活跃读者所需 Blob。
  2. Home/FUSE 进程重启后 Master 的 root 状态与本机文件树核对；新请求重建 FUSE inode/handle。Master 进程重启从跨节点控制记录恢复 root/version 顺序与提交结果；若原 Master 失联，先确证其被围栏，再由恢复进程读取镜像记录。未完成发布通过请求号判断继续、撤销或清理孤儿 Blob。

05 · 可靠性合同与故障表

把“写入成功”“本机 fsync 成功”“两副本镜像发布成功”当作三个不同承诺。Workspace 的故障域是 Home 的本机存储；镜像版本的故障域是副本集合。控制面必须守住单一 Home 与单次版本提交，不能用数据面缓存推导控制事实。

故障切点继续提供什么必须拒绝 / 恢复动作
本地 FUSE daemon 死亡底层普通文件与已发布 Blob 留在磁盘；新 daemon 重挂载后重新 lookup/open。原挂载的旧 FD 和进行中的 FUSE 请求不能透明续接；调用方识别错误并重开/重试。
Home 进程死亡，磁盘仍在重启核对 root epoch、根状态与文件树；新打开恢复。远端旧 handle 可 ESTALE；修改请求返回未知时先解析结果，不能双重执行。
Home VM/磁盘不可达其他 workspace 和已发布镜像仍可用；该 workspace 等原 Home 恢复。不因超时就把 Home 指给 B；永久磁盘损坏首版无法恢复该 workspace。
Master 死亡或网络隔离既有 Home 访问和节点已缓存的、可验证的已发布版本可在原 epoch 继续。新 root / draft、Home 变更、镜像发布/删除等需提交权威状态的动作暂停；Master 不在旧 Home 可能活着时重新指派。对未知版本不能只凭缓存猜测。
镜像发布途中写者/节点死旧版本继续读；未发布 Blob 可被恢复作业核验或稍后 GC。不能把只有一份、缺索引或校验失败的候选标记已发布；请求号用于查询最终结果。
镜像一个持久副本坏/离线从另一份已验证副本或可信缓存继续读，后台重建耐久副本。读前/读后摘要不符就换源并告警；若所有可信来源失效则报错，绝不返回错数据；只剩一份时读可继续，但新发布暂停并告警，待副本恢复。
缓存节点死 / P2P 中断从持久副本回源或其它已验证缓存节点读。缓存消失不减少持久副本计数，不能使正在提交的版本被误认完成。

必须守住的四个不变量

1. 单一 Home

RootCatalog 带持久 epoch；创建/删除走可恢复中间态。无正向围栏证明时不自动更换 Home，避免旧 Home 仍写与新 Home 并写。

2. 身份不混淆

P2P 请求携带 root epoch、文件身份、请求身份；改名/删除后旧句柄不能按同名新路径执行。不同平台若缺可靠文件身份，安装时探测并拒绝不安全模式。

3. 发布只指完整版本

稳定切点、校验通过的 index/Blob、足额不同故障域副本齐备后才原子提交版本可见性。别名是指针，版本 ID 永不原地变更。

4. 回收不伤读者

版本删除先停止新 pin，再等待在用 reader 或保留窗口结束；GC 只删除未被任何发布版本/活跃 reader 引用的数据。

控制记录的耐久方式可采用简单本地事务日志加快照，或外部可靠 KV，但两者都需给出 Master 故障域；不要仅为了引用 3FS 而引入 FoundationDB。首版采用单一 Master 写者 + 两故障域同步镜像控制日志：根 / draft 归属变更与版本发布在控制记录落足两份前不 ACK。任一已确认版本必须有两份 Blob、manifest 和提交记录；节点损失后可从剩余记录恢复。Master 服务不自动选主，旧主未围栏时不启动新写者。可用性 HA 与第三副本/共识是后续独立演进项；数据副本并不自动让 Master 在线。

06 · 先保证正确，再兑现各自的性能

路径基础开销下界 / 优化方向需要白盒观察什么
Home 本地 W1Native FS 是机制参考上界，薄 FUSE 是该入口的成本参考；复用根目录/数据根 FD，减少重复路径解析、回调拷贝与无谓属性请求。FUSE lookup/open/read/write、下层文件 I/O、权限、缓存命中、CPU 与 syscall 分布；同场与默认 MooseFS 比较。
远端 P2P W2/W3批量/合并可合并的请求、连接复用、读打开元信息与小内容同返、按请求范围传输；共享缓存失效成本必须计入。一次应用操作产生的 RPC 数、RTT、排队、A 端文件 I/O 与 B 端 FUSE；与 NFS 和 MooseFS 同场测。
文件树冷启动索引先到、数据按需；小文件 pack 降对象与 RPC 个数；按启动 trace 预取常用路径，热 Blob 多源服务。到首个可运行命令时间、metadata bytes、实际读到的 data bytes、pack 放大、p95 首读与源节点带宽。
磁盘文件启动首版多源并行完整下载、传输块校验/断点续传；下载后本地直接供 Firecracker 使用。全量下载时间、每节点带宽、校验 CPU、启动并发；不把“文件树按需启动”收益套用到它。
发布与副本写者稳定切点之后异步转换/复制；同租户内内容复用与增量父版本候选要经真实命中率证实。切点暂停时间、后台完成时间、每版新增物理字节、两份副本达标时间、失败清理与 GC 成本。

旧 Home 预览版同场 W1 曾明显快于 MooseFS，但那是另一个分支、另一套验收条件；新 AFS 要重跑。实际 Agent 在 Home 的比例决定整体收益：若本地操作比例为 p，平均单操作成本可先用 p × 本地成本 + (1-p) × 远端成本 估算；真实尾延迟、并发干扰和任务完成时间不能这样线性推断，必须跑 Agent trace。镜像的冷启动与 fan-out 应单列测量，不能和 workspace 小文件 W1 混为同一性能排名。

07 · 借鉴开源项目，但不复制其目标

项目可借鉴的机制AFS 的取舍
（3FS）控制面/元数据/存储/客户端分层；副本与读源选择；FUSE 与 native 路径的开销分析。3FS 面向高吞吐集群、FoundationDB 元数据、RDMA 与文件等长 chunk/CRAQ。AFS 2–4 节点 Home 本地主路径不默认采用全局分片/链复制；镜像多副本只借其“可从多份读”的方向，发布规则另定。
（RustFS）S3 兼容对象存储的分层、持久对象接口和运维参考，可作为 Blob 后端候选。它不是 POSIX Home 现成替代；内建一套对象/纠删码集群会增加 2–4 节点运维与语义成本。先定义 Blob 存放接口，再用真实故障/成本测试决定是否接入。
（Nydus）metadata bootstrap 与内容 Blob 分开、内容摘要、按需范围读和预取。AFS 先针对 gVisor 文件树定义最小发布索引；可规划 Nydus/OCI 导入适配，但不声称当前 manifest 就是 RAFS 或必然使用 fscache。
（AgentENV）私有写层、快照工件的完整提交、P2P 在持久源之后加速分发。只借提交/分发边界；OverlayBD/ublk 或 VM 生命周期不强行成为 AFS 文件树模型。其 P2P 配置仍需按产品成熟度独立审查。
（E2B）不可变基础模板 + 沙箱私有写层、缓存/预取、控制与数据角色分离。AFS 只管文件/磁盘内容与版本；E2B 的内存恢复、编排流程和平台合同不自动属于 AFS。
（Firecracker）明确 VM state、memory 与 disk 文件分属不同工件，磁盘由宿主管理。首版磁盘文件全量下载到本地，配单沙箱独立可写层；块级按需读取和完整 VM 恢复另立需求与验收。
旧 AFS/DMS Home 预览本地文件、粗粒度归属、两种远端后端、FUSE inode/handle、故障收敛及 Linux W1/W2 证据。按新双 workload 合同逐块重用，不整目录拷贝旧状态机。具体本地证据见 需求证据。

08 · 实施切面与先验风险

架构设计到代码的顺序应让每步有端到端可观察结果：先让 Master 根归属 + 一个 FUSE 挂载 + Home 本地普通文件闭环；随后 P2P 远端与共享缓存/错误语义，NFS 作为可选后端；再加入私有切点、不可变索引与两节点持久发布；最后把 gVisor 文件树按需读、Firecracker 完整镜像交付、多源缓存和 GC 接通。各步均保持 Linux 构建/测试和对应故障/性能基线，不把尚未实现项藏在开关里。

需要尽早穿刺：共享切换

单 Home 使写入事实源简单，但 FUSE page cache 与多个远端客户端会使 close-to-open 失败。先做 A/B 交替写、不同长度、同名重建、旧句柄、进程故障，检查失效通知和无缓存兜底。

需要尽早穿刺：稳定切点

多文件镜像不能靠扫描活跃目录得到一致版本。先在目标文件系统验证 reflink/快照能力及暂停复制回退，测写者停顿与转换吞吐，决定首版支持的存储前提。Firecracker 私有层还需证明不会直接改写被多沙箱共享的基础磁盘文件。

需要尽早穿刺：两副本发布

在两节点上故障注入：一份复制完成后断电、两份完成但 Master 未提交、提交回复丢失、发布后损坏或丢一份。用固定版本 ID 验证读者永远只见完整版本。

需要尽早穿刺：运行时接入

gVisor 实际 gofer/宿主路径如何经过 AFS mount，以及 Firecracker 使用本地基础磁盘加私有写层的接法、格式和大小，都必须用真实启动验证。单 VM 旧实验只证明若干机制可运行。

演进边界：若后续需要 Home 自动故障接管、完整通用 POSIX、Firecracker 块级懒加载、VM 内存恢复或全局多写镜像，请分别引入副本/围栏、协议与性能合同；不要让不可变版本增一个“可写开关”后悄悄承担这些语义。

09 · 三轮自审与修订记录

轮次审查问题在设计中落实的修订
第 1 轮：需求覆盖“统一 FUSE”是否误写成统一业务后端？Firecracker 磁盘文件是否被当成文件树按需读？把 RootRouter 与两个独立后端分开；明确 Firecracker 首版先完整下载，gVisor 才以文件索引按需读；需求 W0–W5 / I0–I5 分列。
第 2 轮：故障与一致性远端重开读会不会受 FUSE 缓存污染？快照扫描是否会暴露半成品？Master 死后会不会双 Home？共享访问要求缓存收敛或保守无缓存；发布前必须取得稳定切点与足额持久副本；无正向围栏证明不自动换 Home。
第 3 轮：证据与性能是否把旧 Home 数字、RustFS/3FS 功能、单 VM 镜像实验误当新 AFS 成果？交互关系是否可直观看懂？将已有证据、设计目标和未验证点分栏；保留 W1 20% 为目标而非实测；新增 Home 命中率与镜像 fan-out 的独立验收，并补私有 draft 路由及两条端到端时序图。

自审结论：本文可作为实现拆解依据；运行时接入、共享缓存切换、稳定切点和副本故障仍需要真实 Linux 穿刺。设计完成不等于产品验收。
