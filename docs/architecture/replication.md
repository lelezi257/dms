# 复制

DFS 通过副本策略决定 chunk 的持久份数和放置位置。复制发生在文件布局之下，完成后由 Meta 提交副本目录和新文件版本。

## R=1 与 R=N

- R=1 只要求一个可验证持久副本，适合最小功能和开发验证。
- R=N 要求多个同步持久副本，才可用于与 3FS 同条件性能对照。

无论副本数多少，Meta 只应在收到可验证 receipt 后提交新版本。验证缓存不能自动算作持久副本，除非经过提升并提交。

## 一写多读

当前 DFS 优先验收一写多读：一个 writer 完成确认写入后，多 reader 读取同一内容并保持版本一致。更复杂的并发写、故障注入、长时间运行和大规模矩阵后置。

## 当前状态

DFS 持平 3FS 的目标只适用于同接口、三份同步持久副本条件。缺少合格 3FS 对照时，功能可以登记通过，性能保持待验收。
